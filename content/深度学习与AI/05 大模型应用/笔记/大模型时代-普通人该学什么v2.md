## 2026年, 模型研发门槛已经抬到云端

若你还在犹豫要不要从零啃 Transformer, 亲手训一个7B 模型，不妨先退一步，看看这门行业是怎么把财富与人力像磁铁吸铁屑一样，集中到产业链最上游的。

Sam Altman 执掌 OpenAI, Forbes 实时榜单估算其个人净资产约三十四亿美元。Anthropic 联合创始人 Dario Amodei 在 2026 年初一轮约 9650 亿美元估值的融资后，外媒估算其个人身家已达 80 亿美元量级，跻身全球五百富豪榜。视线回到国内。猎聘与 36 氪等渠道的 2026 年数据显示，AI 新发岗位平均月薪已突破六万元；深度学习架构师年薪天花板接近 300 万元；字节, 阿里, 腾讯的 Top Seed 与青云计划，应届 AI 博士总包可达 130 万以上；个别核心人才传闻总包接近亿元，含期权与长期激励。这些数字指向同一个结论：预训练, Scaling Law, 万卡集群调度, RLHF 对齐，这条链的上游早已被顶尖人才锁死，普通人靠情怀和一块 3060 是挤不进去的。若还把成为下一个 Karpathy 当默认路径，多半会在 GPU 电费账单与论文 deadline 里耗尽热情，离真实的价值创造反而越来越远。跟指望靠自学理论物理去发现新粒子差不多。这并非劝退，而是重新定位。大模型的训练权已高度集中；使用权仍是一片待垦的广阔地带，而且土地便宜, 门槛低。理解 [[自回归模型_百度百科|自回归模型_百度百科]] 与 [[RNN-到-Transformer|RNN-到-Transformer]] 的脉络，有助于看清我们正站在产业链的哪一段，而不必误以为必须亲自完成预训练才算入门。你不用会造发动机，也能把车开得很好。

## 普通人真正该学的东西

当造模型成为少数人的游戏，用模型就成了多数人的主战场。此处的"用"，不是把 AI 当搜索引擎糟蹋，那种用法约等于买了台跑车用来拉煤气罐。科学地使用 AI，至少包含四层能力:

- 第一，理解边界。模型会幻觉, 会顺从, 会过度自信——一个信心满满地胡说八道的助理，比一个诚实说"我不知道"的助理更危险。概率性输出不能当作确定性事实。关于幻觉与顺从，后文第四节有对照表；检索增强与人工核验可参见 [[InfoRet_Lecture_Notes|InfoRet_Lecture_Notes]]。
- 第二，任务分解。把复杂问题拆成 AI 擅长的部分（归纳, 翻译, 格式转换, 初稿生成）与人必须负责的部分（判断, 责任, 伦理, 最终决策）——大致相当于把切菜洗菜外包出去，颠勺这道工序自己留着。
- 第三，迭代协作。用 prompt, 上下文与工具调用，把 AI 当作可调试的协作者，而不是一次性许愿的神灯。神灯精确执行你说出口的字面意思，往往不是你真正想要的结果。
- 第四，安全使用。防 prompt 注入, 防数据泄露, 防过度依赖；职场场景见 [[#七, 员工用 AI 要注意什么]]；日常技巧见 [[#六, 使用 AI 的实用技巧]]。安全地使用 AI，在 2026 年已不再是可选项。企业把内部文档喂给公有 API 导致泄露的案例屡见不鲜；个人把 AI 生成的医疗或法律建议当作最终结论，同样危险。普通人需要建立的，是一种 AI 素养：类似开车要考驾照，使用大模型也需要基本的安全意识与操作规范——区别在于，驾照考不过顶多多学几次，AI 素养不过关，代价可能是密钥, 隐私或者一场官司。

## AI 不是逃避困难的借口

有一种误读很流行：有了 AI，人就可以变懒；有了 Copilot，初级工程师就可以不思考。这就像有了洗衣机，就以为自己再也不用出门赚钱买洗衣粉了。

AI 的价值在于接管机械的, 重复的, 低信息增量的劳动：整理会议纪要, 生成样板代码, 提取 PDF 表格, 批量翻译, 格式规范化。把这些交给 AI，是为了把人的时间还给创造力, 判断力, 整合能力和责任承担能力，而不是还给刷短视频。一个会用 AI 的工程师，不应比不会用的工程师思考地更少，而应在同样时间里思考地更深。AI 是杠杆，不是拐杖。杠杆放大的是你原本的能力方向；你若本来就在逃避困难，它只会让你摔得更快, 更远, 姿势更狼狈。

## 基本概念速查

在动手之前，先把市面热词与底层概念对齐: 这一节就是词典，建议先囫囵翻一遍，遇到不懂的词再回来查。本节与 [[机器学习与深度学习基本概念-KKRRd34S|机器学习与深度学习基本概念]] 对照阅读，可补全传统机器学习与深度学习的地基。

### 1 Agent 相关

Agent：能感知环境, 调用工具, 多步执行目标的 AI 系统。不只是聊天，而是真的会干活的 AI——区别于话痨型聊天机器人，它更像一个愿意主动倒垃圾的室友。早期形态可回溯 [[Auto-GPT-完全体, 全部功能(联网, 文本, 语音, 图像)安装教程|Auto-GPT-完全体, 全部功能(联网, 文本, 语音, 图像)安装教程]]；今日工程化实现见 OpenHands, LangGraph 等开源项目。

- Skill：封装好的能力模块，例如读 PDF, 搜网页, 写 Obsidian 笔记。相当于给 Agent 挂了几个趁手的技能包。
- Rule：持久化的行为约束，例如禁止改 git config, 飞书以 pull 为主。告诉 Agent 不能做什么, 必须怎么做——说白了就是家规。
- Hook：在 Agent 生命周期特定节点自动触发的脚本，例如会话开始时同步配置。自动化每次都要做的琐事，免得每次都要手动提醒。
- Plan：复杂任务先拆步骤再逐步执行的模式，即 Plan-and-Execute. 先列计划再动手，能显著减少 Agent 盲目试错, 原地转圈的概率。
- MCP：Model Context Protocol，LLM 连接外部工具的标准协议。可理解为 AI 世界的 USB-C：文件, 数据库, API 经此统一接入，不用每次都焊一根新线。官方架构说明见文末参考链接。

> Rule 管边界，Skill 管能力，Hook 管时机，Plan 管步骤，MCP 管连接。

### 2 LLM 相关

- Token：模型处理文本的最小单位。中文约 1 至 2 字 per token，英文约 4 字符 per token. 计费与上下文窗口上限均按 token 计算, 本质上是模型世界的流量费。
- Quota：API 或产品的用量配额，如 RPM, TPM, 每日消息数。超限会触发 429 或降速；企业常按 seat 分配，超额了就得等下一顿。
- Embedding：把文本变成高维向量，用于语义相似度检索。RAG 与 Smart Connections 的核心；入门可读 [[Word-Embedding|Word-Embedding]]。
- 语义 Semantic：意思相近而非字面相同。"汽车"与"轿车"语义近；关键词搜索找不到时，向量搜索往往可以，因为它理解的是"意思"而不是"字面"。
- Context Window：模型一次能看见的最大 token 数，如 128k, 200k. 超长文档需切 chunk 或摘要，否则模型会像被塞太满的胃一样开始消化不良。
- Temperature：采样随机性。事实问答宜用低 temperature；头脑风暴宜用高 temperature. 低温让模型规规矩矩答题，高温让它开始天马行空。
- System Prompt：设定模型角色与行为的全局指令，相当于岗位说明书。OpenAI Tokenizer 与 Hugging Face NLP 课程见文末参考链接；库内教程见 [[Huggingface-Transformers-教程|Huggingface-Transformers-教程]]。

### 3 大模型特有问题

- 幻觉 Hallucination：模型自信地编造不存在的事实, 引用或数据，语气笃定到你都开始怀疑自己。应对：要求引用来源, RAG grounding, 人工核验关键结论。
- 顺从 Sycophancy：模型倾向于同意用户，即使用户错了——本质上是个过度友善的应声虫。应对：明确请 AI 找漏洞, 唱反调；或多 Agent 辩论。
- 知识截止：训练数据有时间边界，不知最新事件，相当于一个刚从长期出差回来的同事。应对：联网搜索, 私有知识库, 注明日期。
- Prompt 注入：恶意输入试图覆盖 system 指令，属于社会工程学在 AI 身上的变种。应对：输入过滤, NeMo Guardrails, 不把 secrets 放进 prompt.Anthropic 防护指南见文末参考链接。

### 4 Code AI 与通用 AI

- Code AI: 优化代码补全, 仓库理解, 终端与 IDE 集成；自动读项目文件, git diff, linter；风险在于误改代码, 执行危险命令；适合开发, DevOps, 数据脚本。
- 通用 AI: 优化对话, 写作, 推理, 多模态；主要靠用户粘贴或上传；风险在于泄露粘贴的机密文档；适合文案, 分析, 学习, 非代码自动化。两者边界正在模糊：通用 AI 也能写代码，Code AI 也能写文档。选哪个，看主战场是否在代码仓库里。想从底层理解语言模型，[[LLMs-from-scratch-rasbt|LLMs-from-scratch-rasbt]] 是难得的动手路径，适合手痒又不怕啃硬骨头的人。

### 5 市面产品形态

- AI Chatbot：豆包, Kimi等。对话式问答。
- AI Agent：Trae solo, kimi work, workbuddy等。多步执行, 调工具, 能完成任务。
- AI Copilot：Microsoft 365 Copilot等。嵌入现有软件，辅助而非替代工作流。
- AI Search：秘塔, Kimi 搜索。搜索加合成答案加引用。
- AI Workflow：Dify, Coze等。可视化编排自动化流水线。
- AI RAG 应用：NotebookLM等。上传文档，私有知识问答。
- AI Coding IDE：Trae IDE 等原生 Agent 加代码模型。
- Local LLM：Ollama 加 Open WebUI, LM Studio. 本地跑模型，数据不出机器。

> Agent 有时指聊天机器人，有时指能改代码的系统。具体是否是 agent 要看能力：能否持久状态, 能否调用工具, 能否多步规划。LangChain Agent 框架梳理见文末参考链接。

### 4 AI Debate

单模型一旦开头错了，后面会越写越自信，属于典型的"一步错步步错，还错得振振有词"。多 Agent 辩论可以纠正这种盲区。代表项目：

- MAD（arXiv:2305.19118）；
- Berkeley LLM Debate；
- MALLM（EMNLP 2025 Demo）；
- Cultural Debate（ACL 2025 Oral）。重要决策时，让两个不同模型分别分析，第三个模型做仲裁摘要；开发者可用 MALLM 试验 Expert, Skeptic, Judge 三角流程。相当于开个小型辩论赛，让模型们互相拆台，真相往往在拆台声中浮现。

### 7 Obsidian & AI Agent 知识库

2026 年最值得关注的一股潮流 -- 就是 Obsidian 作界面, AI Agent 作维护者的"karpathy llm wiki".  
Andrej Karpathy 在 llm-wiki gist 中系统阐述了这一模式，堪称"让 AI 给自己盖房子还顺手打扫"的典范。

![${date}-${noteName}-${prompt}-4](attachments/RovGdPOGpomrJ2xIerUchCBcnIb/img_005.png)

<p class="kb-image-caption">${date}-${noteName}-${prompt}-4</p>

- Karpathy 的论点是：传统 RAG 每次 query 都从 raw 重新检索，知识不积累；LLM Wiki 则让模型持续编译一份持久的 wiki，交叉引用与矛盾标注在 ingest 时就已写入，query 时直接读编译好的结构。Obsidian 是 IDE，LLM 是程序员，wiki 是 codebase——这套比喻精妙得让人想给它鼓掌。

- 三层架构与本库 llm-wiki 规则一致：raw 为不可变源材料；content 为编译后的 wiki 正文；XXX.md 或 AGENTS.md 为 schema；index/knowledge-index.md 为全局目录；index/wiki-log.md 为 chronological 审计。

- 三种核心操作：Ingest，丢源文件，Agent 读, 写 summary, 更新 entity 页, 维护 index, 记 log；Query，问问题，Agent 查 index, 读相关页, 合成答案，好答案可归档回 wiki；Lint，查矛盾, 孤儿页, 过时 claim, 缺 cross-ref——相当于让 AI 定期给自己的知识库做一次体检。

- 工具栈：Obsidian 阅读与 Graph View；AI Agent 维护；Smart Connections 做本地 embedding 语义关联；Copilot 插件做 Vault Q&A；Obsidian CLI；wiki 变大后可加 qmd hybrid 检索；Git 提供版本历史。

- 起步：读 Karpathy gist，粘贴给 AI；建 raw, contentm, XXX.md；Obsidian 打开 vault，Graph View 观察知识生长——那种看着知识图谱一点点长大的成就感，跟看豆包学会新指令时差不多。相关文章与插件见文末参考链接。

## AI 的实用技巧

本节不谈宏大架构，只谈日常里立刻能用的习惯。每条技巧后面附一句原理：知道为什么有效，比背口诀更重要。相关工具与文档统一见文末参考链接。

### 1 用 Markdown 和 AI 说话，而不是 Word

Word 的 docx 本质是压缩包里的 XML，模型要先解压, 剥离样式, 再猜结构；Markdown 则是纯文本，标题层级, 列表, 表格在字面上就写清楚了。大模型训练语料里 Markdown 极多，同等信息量下 token 往往比 docx 少三成到五成，回答质量也更稳定。可以显著地给模型节省"翻译成本"。实践上, 往往让模型直接输出 Markdown；需要交 Word 时可以再本地用 Pandoc 转一次。对外正式公文仍需使用 Word. 内部知识, 笔记, 给 AI 的上下文，优先 Markdown. 本库全文即如此；  
Obsidian vault 与 [[index/MOC-dl-ai]] 下的笔记均可直接被 Agent 读写。Pandoc, MarkItDown 与格式路由讨论见文末参考链接。

### 2 会动的网页，往往比 PPT 或视频更好生成

模型读写过整个互联网，HTML 与 CSS 是母语；PowerPoint 是嵌套 XML 或二进制，模型既看不见也难精修。因此, 演示, 可视化说明, 交互 demo，优先生成一份单文件 HTML，浏览器双击即可播放；动画用 CSS 或 GSAP，图表用 Mermaid 或 Chart.js，成本远低于导出视频或手工排版 PPT. 原理: 这些格式的生成路径短。HTML 是一步到位；PPT 常需先 Markdown 再转 pptx，或生成图片再贴进幻灯片，每一步都可能丢编辑性，跟传话游戏一样传几手就走样。若对方必须要 editable 的 pptx，再让 Agent 走 HTML 设计后转原生对象，而非先要视频。Marp 可把 Markdown 直接变成幻灯片，与本库 Obsidian 工作流兼容。

### 3 Sandbox 与 Allowlist：Agent 的套马杆

在 Trae 等 Agent IDE 里，Shell 命令默认能读你所能读的文件, 执行你所能执行的命令, 某种意义上是给了 Agent 一把和你一样大的钥匙。Sandbox 在操作系统层限制文件系统, 网络与临时目录；Allowlist 则列出无需每次点批准的命令或 MCP 工具。二者叠加, Allowlist 决定哪些调用可以自动执行，Sandbox 决定即使自动执行也在特定范围里。

Run Mode 通常有三档：

- Auto-review 默认，对 allowlist 内命令直接执行，对其余走分类器或弹窗；
- Allowlist 模式更严；
- Run Everything 适合隔离环境，生产环境慎用。

### 4 结构化输出：让人和机器都能解析

需要 JSON, 表格, 固定字段时，不要只在 prompt 里写"请返回 JSON"然后祈祷。应使用 API 的 structured output 或 JSON Schema 模式，应用层再用 Pydantic 等校验；失败时把校验错误贴回模型重试两三次。原理：约束解码或服务端 schema 从生成阶段就禁止胡写括号，比事后 regex scrape 可靠一个数量级。

### 5 复杂推理：分步想，分步跑

数学, 法务分析, 架构权衡等多步任务，显式要求逐步推理，或先出大纲再填细节。对关键结论可开两次独立对话取交集，即自洽性检查的朴素版；与本文 5.4 节的 AI Debate 同源。原理：Transformer 单轮生成是贪心；中间步骤写出来，等于人为把搜索路径拓宽了。

### 6 Few-shot：用例子规定格式

与其长篇描述输出格式，不如给两到三个输入输出样例。让模型从样例里学顺序, 语气, 边界情况，比给一堆形容词有用得多, 毕竟"举个例子"永远比"你懂我意思吧"更有效。原理：in-context learning，注意力会强烈对齐示例 token 模式。

### 7 把 prompt 写进文件

XXX.md, AGENTS.md, xxx/rules 里的 Rule，本质是把 system 指令版本化。聊天窗口刷新就丢失了；文件进 Git，可 diff, 可回滚, 可团队共享。Karpathy LLM Wiki 的 schema 层即此意；

> 本库见 llm-wiki 规则与 [[Auto-GPT-完全体, 全部功能(联网, 文本, 语音, 图像)安装教程|Auto-GPT-完全体, 全部功能(联网, 文本, 语音, 图像)安装教程]] 时代以来的 Agent 配置演进。

### 8 表格数据用 CSV 或 JSON

十行以上的结构化数据，贴 CSV 或 JSON 块；模型对列对齐, 缺失值, 单位更敏感。原理：分隔符明确，token 边界清晰，减少模型把数字当句子读错的概率。数字排成表格，模型才不会数着数着把小数点搞丢。

### 9 长文用分块流水线

大纲, 初稿, 审阅, 润色分成多轮或多 Agent 步骤，每步验收再进下一步。原理：错误在短链路里更易定位；与 [[InfoRet_Lecture_Notes|InfoRet_Lecture_Notes]] 里分阶段检索同理，单次 context 塞满反而稀释注意力。

### 10 先让 AI 提问，再让 AI 动手

需求模糊时，先要求它列出还需要澄清的问题，你答完再生成。原理：减少模型为填空白而幻觉；相当于 cheap 的 human-in-the-loop 门控，花两句话的成本，省掉返工的成本。

### 11 视觉任务直接截图，少描述

UI 错位, 曲线异常, 公式排版，截图加一句指出问题区域，多模态模型比纯文字描述高效得多。原理：像素携带的信息密度远高于冗长形容, "这里歪了"配一张图，胜过五百字的方位描述。

### 12 评估比调 prompt 更重要

改 prompt 前先准备十到五十条真实用例，改完对比通过率。Promptfoo 等工具可自动化。原理：没有度量，优化只是换一句更好听的咒语——你以为在调参，其实是在换着花样碰运气。

## 员工用 AI 要注意什么

公司允许员工使用 AI，不等于允许员工随意使用 AI. 这跟公司允许你用打印机，不等于允许你拿去打印自己孩子的作业是一个道理。

### 1 五条红线

- 机密不进公有 API. 未脱敏的客户数据, 源码, 财务, 人事, 合同原文，禁止粘贴到网页版 AI 等第三方，除非企业已采购私有部署或 DPA.
- AI 输出必须人工审核。对外邮件, 法律意见, 医疗建议, 安全相关配置, 财务数字，生成不等于审核通过。AI 交的是初稿，不是终稿。
- 标注 AI 辅助。对外文稿若大量采用 AI 生成，按公司政策标注；
- 不甩锅给 AI."是 AI 说的" 不是免责理由；署名人对发布内容负责，就像不能因为菜谱写错了就怪厨师没文化。
- 遵守许可证。AI 生成的代码可能撞开源协议；商业项目需审查依赖与版权。

### 2 案例

- 案例一，三星工程师 paste 源码进 AI. 2023 年, 多名员工将会议录音转文字, 内部 bug 相关源码粘贴到 AI 做摘要与 debug. 公司紧急限制 AI 上传容量。教训：源代码与内部 bug 描述属于机密；应使用企业版 Copilot, 私有部署，或仅粘贴脱敏后的最小复现。
- 案例二，律师引用 AI 虚构判例。律师用 AI 检索案例，AI 编造了不存在的判例；律师未核实即提交法庭, 法院制裁律师。教训：法律, 医疗, 金融事实必须可追溯来源；AI 幻觉在严肃领域代价极高。
- 案例三，员工用 AI 写官方邮件。HR 或主管用 AI 批量生成冷漠的通知，未修改即发送。教训：AI 适合起草；涉及人的关系的文本，语气与事实必须人工把关。
- 案例四，开发把 API Key 写进 prompt. 员工将 production API key, 数据库连接串粘贴进对话；对话可能被 logging 或第三方插件读取, 密钥泄露, 账单被盗刷。教训：Secrets 永不进 prompt；用环境变量；企业应配 secret scanning.
- 案例五，用 AI 生成虚假实验数据。研究者用 AI 生成看似合理的实验数值或参考文献，未实际做实验。论文撤稿, 学位取消。教训：AI 不能替代实验, 测量与原始记录；raw data 与 AI 生成分离。
- 案例六，客服 AI 胡说承诺优惠，如2024 年某航空公司类事件。面向客户的 chatbot 在无授权情况下承诺退款, 升舱，客户截图维权。教训：对外 Agent 必须输出过滤, 禁止域外承诺, 保留人工升级路径。

### 3 企业可执行的最低规范

- 分级数据：公开, 内部, 机密, 绝密；仅公开与部分内部可进批准过的 AI.
- 企业 AI 账号：统一采购, 审计 log, 关闭用于训练选项。
- 培训：入职 AI 安全课加年度更新。
- 事件响应：误粘贴机密后立即轮换密钥并报告安全团队。
- 模板：可 AI 辅助任务清单与禁止 AI 任务清单。

## 结语

大模型研究的轰轰烈烈属于少数顶尖人才；网站上十四万 star 的 Dify, 十一万 star 的 Ollama, 七万 star 的 OpenHands, Karpathy 的 LLM Wiki 范式，这些才是普通人真正的杠杆。学习如何科学, 安全地用 AI, 才是普通人应该做的；让 AI 代替人类去做机械, 重复的事，从而解放人力去做更有创造力, 挑战性的事情；

不必痴迷 AI，也不必排斥 AI. 速冻水饺大多不如手工好吃，但让更多人吃得起干净, 像样的饺子。先有能力做速冻水饺，再来谈手工的美味和讲究。时代不会因为我们的情绪而停下。它会奖励那些看清门槛, 重新定位, 动手实践的人。
