# 衡量大语言模型（LLM）推理效率：四大核心指标解析

> 来源：[偲倢科技 Spingence](https://www.spingence.com/technology-detail/measuring-LLM-Efficiency/) · 2025-01 · 正文为繁体中文原文

![](https://www.spingence.com/upload/news_technology_b/twL_news_technology_25J01_N3LhToTlIb.png)

隨著生成式 AI 的快速普及，越來越多企業開始導入大語言模型（LLM）來支援客服, 知識檢索, 自動化文件生成等應用。然而在選擇模型或服務方案時，很多人往往只看"準確度"或"模型大小"，卻忽略了 **推論效率** 。推論效率不僅影響使用者體驗，也直接關係到系統能否支撐大規模應用，以及背後的硬體成本。

## 為什麼推論效率這麼重要？

![](https://www.spingence.com/upload/news_technology_b/twL_news_technology_25J01_seUIgVnBWz.png)

- **使用者體驗**：回覆太慢會降低對 AI 工具的信任。
- **業務可擴展性**：TPS 過低則無法支撐大量請求。
- **成本效益**：更高效代表更少硬體處理更多任務。

## 四大核心指標

![](https://www.spingence.com/upload/news_technology_b/twL_news_technology_25J01_OpBVpzcKQ6.png)

### 1. 反應速度 — Time to First Token (TTFT)

從送出請求到模型產生第一個 token 的延遲。對話/客服場景通常要求更低 TTFT；長報告生成可容忍較長等待。

### 2. 輸出速度 — Token Per Second (TPS)

每秒生成的 token 數，衡量長文本吞吐。高 TPS 意味更快完成長文生成。

### 3. 輸出穩定性 — Time per Output Token (TPOT)

平均每個 token 的生成時間。TPOT 越低越穩定；偶發飆升會造成輸出"斷斷續續"。

### 4. 流暢度 — Inter Token Latency (ITL)

相鄰兩 token 之間的平均延遲，比 TPS 更貼近"打字機"體感。ITL 過高會像一格一格跳字。

## 場景參考阈值（可依業務調整）

| 場景 | 參考 |
| --- | --- |
| 高互動對話 | TTFT < 500ms，ITL < 200ms |
| 長文生成 | TPS > 50 token/s，TPOT < 50ms |
| RAG 檢索問答 | TTFT < 50ms，ITL < 50ms，TPOT < 80ms |
| Agent 跨系統流程 | TPOT < 100ms，ITL < 250ms |

## FAQ 摘要

- **TTFT vs TPS**：對話重 TTFT；長文生成重 TPS.
- **ITL vs TPOT**：TPOT 偏整體平均速度，ITL 偏使用者流暢感。
- **合格標準**：無通用絕對值，應按應用與使用者可接受範圍定義。
